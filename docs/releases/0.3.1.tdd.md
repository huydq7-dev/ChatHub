# ChatHub 0.3.1 — notification regressions

Source: PR #1 review and the user's request to fix both findings and release 0.3.1.

## User journeys

- An active chat retains native focus after initial navigation, another navigation,
  and an appearance change. Background chats remain unfocused.
- Clicking a notification invokes that notification's callback. Unknown, closed,
  evicted, or previous-document callbacks never open another conversation.

## RED → GREEN evidence

- RED checkpoint `ec83ea0`: `node --test scripts/test-notifications.mjs`
  executed seven tests: one passed, six failed. The real WebKit
  `BrowserNotificationTests` focus test failed six expectations across three
  document loads. The fixture used synthetic HTML at `fixture.invalid`.
- GREEN checkpoint `972a477`: the same seven JavaScript tests and the WebKit
  focus regression passed after the fix.
- Final validation adds two JavaScript edge cases and a native-to-JavaScript
  click integration test. No real notifications or messages are sent.

| Guarantee | Test | Type | Result |
| --- | --- | --- | --- |
| Native focus is available before provider scripts and restored after navigation | `BrowserNotificationTests.nativeFocusSurvivesNavigationAndAppearanceChanges` | WebKit integration | PASS |
| Native click dispatch reaches the second untagged notification only; malformed/empty IDs are harmless | `BrowserNotificationTests.nativeClickRoutesToTheMatchingJavaScriptNotification` | WebKit integration | PASS |
| Untagged and long-tagged notifications retain independent callback IDs | `scripts/test-notifications.mjs` | Shipped bridge in Node VM | PASS |
| Unknown, closed, evicted, and previous-document IDs never fall back to another callback | `scripts/test-notifications.mjs` | Shipped bridge in Node VM | PASS |
| Provider replacement tags remain separate from callback identity | `scripts/test-notifications.mjs` | Shipped bridge in Node VM | PASS |

## Coverage and limits

Swift coverage was collected in `.build/arm64-apple-macosx/debug/codecov/ChatHub.json`.
Whole-binary line coverage is **14.79%**, including the largely unautomated native
UI. BrowserSession line coverage is **36.58%**; the native click-dispatch method's
three regions are all covered. This is not a claim of 80% whole-app coverage.
Node's test-coverage report excludes VM-evaluated source and is not used as a
bridge coverage percentage.

The tests cover the shipped JavaScript, document-start injection, navigation,
appearance changes, and Swift click dispatch. macOS notification delivery and
authenticated provider login/send/receive remain manual checks. A notification
whose callback belongs to an old document only selects its account; it never
guesses a conversation.
